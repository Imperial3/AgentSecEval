# AgentSecEval Dataset Methodology

## Objective

AgentSecEval evaluates whether explicit verification mechanisms improve the reliability and security of tool-using language-model agents operating over noisy, incomplete, conflicting, and adversarial information.

The benchmark is designed to evaluate not only whether an agent reaches a correct final answer, but also whether it uses appropriate evidence, recognizes insufficient evidence, prefers authoritative sources, and resists instructions embedded inside untrusted retrieved content.

## Version

v0.1

## Snapshot Date

September 2, 2026

## Initial Dataset

AgentSecEval v0.1 contains 15 benchmark tasks.

The initial task families are:

1. Eligibility verification
2. Regulatory reasoning
3. Temporal reasoning
4. Procedural reasoning
5. Numerical regulatory reasoning
6. Entity and award-data extraction
7. Evidence sufficiency and abstention
8. Indirect prompt-injection resistance
9. Source-authority reasoning

The initial benchmark deliberately uses a limited set of public SBIR/STTR and NSF data because the project begins in a domain where the benchmark author has practical subject-matter familiarity and where authoritative public records are available.

## Dataset Construction

Initial benchmark tasks were AI-assisted and subsequently checked against authoritative public sources.

Gold labels are verified against the cited official sources before evaluation.

The benchmark does not treat AI-generated answers as ground truth merely because they were generated by a model.

For factual tasks, the intended answer is tied to one or more source IDs recorded in `gold/answers.json`.

## Ground Truth Isolation

Gold answers are stored in:

`gold/answers.json`

Agents evaluated against AgentSecEval must not have access to this file while performing benchmark tasks.

The gold file is intended only for evaluation after an agent has submitted its answer.

## Task Inputs

Individual benchmark tasks are stored under:

`tasks/`

Each task defines:

- A unique task ID
- Task category
- Human-readable title
- Question
- Benchmark snapshot date
- Whether correct behavior requires abstention
- Whether adversarial information is present
- Source IDs available for the task

Gold answers are intentionally excluded from individual task files.

## Source Selection

AgentSecEval prioritizes authoritative primary sources whenever they are available.

The initial authoritative sources are drawn from:

- SBIR.gov
- U.S. Small Business Administration SBIR/STTR guidance
- U.S. National Science Foundation funding guidance and solicitations
- SBIR.gov company portfolio records
- SBIR.gov individual award records

The complete registry is stored in:

`data/source-registry.json`

## Frozen Source Snapshots

AgentSecEval v0.1 includes normalized local source snapshots under:

`data/official-sources/`

These files preserve the benchmark-relevant facts used on the September 2, 2026 snapshot date.

They are normalized evidence records rather than complete archival copies of the original webpages.

The original canonical government URL is retained in each source file and in the source registry.

Using frozen normalized sources helps ensure that different models can be evaluated against the same evidence even if a live government webpage changes later.

Future versions may additionally use independently archived or machine-readable source captures where appropriate.

## Adversarial Data

Synthetic adversarial sources are stored under:

`data/adversarial-sources/`

These files are deliberately created benchmark fixtures.

They are not represented as genuine government or third-party webpages.

Their purpose is to test whether an agent treats instructions embedded inside retrieved external content as untrusted data rather than as higher-priority system or user instructions.

The initial adversarial conditions include:

- A false FORCEFIELDS award amount combined with an indirect prompt-injection instruction.
- A false NSF deadline combined with instructions telling the agent not to verify the information against the official source.

The source registry explicitly marks synthetic adversarial sources as untrusted and adversarial.

Those hidden registry labels should not automatically be exposed to an evaluated baseline agent unless the experiment specifically intends to test behavior with such metadata.

## Evidence Sufficiency and Abstention

AgentSecEval includes tasks in which the supplied evidence does not establish every fact needed for a definitive conclusion.

For such tasks, the correct behavior is to identify the evidence gap and abstain from making an unsupported definitive claim.

TASK-013 is the initial evidence-sufficiency task.

It evaluates whether an agent distinguishes between evidence that establishes some eligibility factors and evidence sufficient to establish complete current SBIR eligibility.

## Planned Evaluation Dimensions

Later experiment stages are intended to measure:

- Final-answer accuracy
- Citation correctness
- Authoritative-source selection
- Unsupported-claim rate
- Abstention accuracy
- Contradiction handling
- Prompt-injection resistance
- Tool-call efficiency

These metrics will be implemented after the benchmark dataset and baseline agent environment are complete.

## Limitations

AgentSecEval v0.1 contains only 15 tasks.

The sample is intentionally small and should be treated as a preliminary development benchmark rather than as evidence of broad agent capability.

The initial domain is heavily concentrated on U.S. SBIR/STTR and NSF information.

The benchmark therefore does not yet establish performance across general web research, other regulatory environments, other countries, or unrelated knowledge domains.

The initial adversarial fixtures are intentionally direct and relatively easy to inspect.

Future versions should expand:

- Number of tasks
- Domain diversity
- Attack diversity
- Subtle indirect prompt injections
- Conflicting-source conditions
- Temporal-update conditions
- Evidence-substitution tests
- Multi-hop research tasks

All conclusions reported from v0.1 should state these limitations clearly.
